1. COS'È VERTEX
---------------

Vertex è un client BitTorrent nativo per macOS:
- interfaccia SwiftUI in italiano, tema chiaro/scuro/sistema;
- motore libtorrent 2.1 tramite bridge C++/C;
- aggiunta da magnet, file .torrent, drag & drop, appunti e apertura dal Finder;
- ricerca, filtri, ordinamento, pannello dettagli con file/priorità/tracker;
- resume data, pausa/ripresa, errori, limiti di velocità, porta, DHT, UPnP/NAT-PMP;
- pannello Diagnostica rete con porta effettiva, IP locale, mapping UPnP/NAT-PMP e test
  TCP esterno tramite check-host.net.

Il progetto è pubblico con licenza MIT:
- Repository: https://github.com/cicciocanestro/vertex
- Release: https://github.com/cicciocanestro/vertex/releases
- Ultima release: v1.3.2

- Homebrew in /opt/homebrew.
- libtorrent-rasterbar 2.1.2_2

- openssl@4 4.0.3
- Strumenti disponibili: notarytool, stapler, spctl, codesign, hdiutil, SetFile.
- Nessun certificato di firma installato (security find-identity -> 0 valid identities).

IMPORTANTE — SwiftUI macros:
I Command Line Tools non includono il plugin SwiftUIMacros. Di conseguenza @State non
compila ("external macro implementation type SwiftUIMacros.StateMacro could not be found").
Il progetto NON usa @State. Usa invece:
- UIState<T> (Sources/Vertex/Design/UIState.swift): classe ObservableObject con @Published.
- @StateObject / @ObservedObject per conservare e osservare lo stato locale.

Se un giorno viene installato Xcode completo, si potrebbe refactorare a @State, ma non è
necessario. NON introdurre @State con l'ambiente attuale: la build fallirà.

Altre macro SwiftUI come @StateObject, @ObservedObject, @Environment, @AppStorage,
@FocusState, @Binding funzionano con i CLT.


4. BUILD, RUN, DMG
------------------

Installazione dipendenze:
  brew install libtorrent-rasterbar boost openssl@4

Build release + app bundle:
  ./build.sh

Build debug:
  ./build.sh debug

Esecuzione suite di test automatica:
  ./build.sh test
  (oppure: swift run VertexTestRunner)

Avvio:
  open dist/Vertex.app

Solo SwiftPM (senza bundle):
  swift build -c release
  swift build -c debug

Se Homebrew non è in /opt/homebrew:
  export HOMEBREW_PREFIX="$(brew --prefix)"

Package.swift legge HOMEBREW_PREFIX e usa come fallback /opt/homebrew. I percorsi di
libtorrent 2.1 e openssl@4 sono hardcoded nel manifest e in build.sh: se Homebrew aggiorna
le versioni delle dylib, aggiornare i nomi dei file.

Cosa fa build.sh:
1. se invocato con 'test', esegue la suite con 'swift run VertexTestRunner';
2. swift build -c release/debug;
3. crea dist/Vertex.app;
4. copia Info.plist e icona (generata da Scripts/make-icon.swift se manca);
5. copia Resources/Licenses nel bundle;
6. copia libtorrent-rasterbar 2.1 e libssl/libcrypto 4 in Contents/Frameworks;
7. riscrive gli install name a @executable_path/../Frameworks e @loader_path;
8. firma ad-hoc le dylib e l'app;
9. verifica che l'eseguibile non contenga più percorsi /opt/homebrew.

Creazione DMG:
  ./Scripts/make-dmg.sh              # ricompila e crea la DMG
  ./Scripts/make-dmg.sh --no-build   # usa dist/Vertex.app esistente

La DMG contiene Vertex.app, il link ad Applicazioni, Leggimi.txt e .VolumeIcon.icns.
Lo script verifica la firma del bundle montato e genera il file .sha256.

ATTENZIONE: se in futuro firmi l'app con Developer ID, NON rilanciare build.sh prima di
creare la DMG: build.sh rifirma in ad-hoc. Usa ./Scripts/make-dmg.sh --no-build.

6. BRIDGE CTORRENT — API E COMPORTAMENTO
----------------------------------------

Header pubblico: Sources/CTorrent/include/vertex_torrent.h

Funzioni principali:
  vt_session_create(download_dir, resume_dir, port, down_limit, up_limit, enable_dht)
  vt_session_destroy(session)
  vt_session_poll(session)
  vt_snapshot_json(session)
  vt_detail_json(session, torrent_id)
  vt_last_error(session)
  vt_magnet_uri(session, torrent_id)
  vt_add_magnet(session, uri, save_path, paused, sequential)
  vt_add_torrent_file(session, path, save_path, paused, sequential)
  vt_control(session, torrent_id, action)
      action: pause, resume, reannounce, sequential_on, sequential_off,
              remove, remove_files
  vt_set_file_priority(session, torrent_id, file_index, priority)
  vt_apply_settings(session, port, down_limit, up_limit, enable_dht, enable_upnp)
  vt_free_string(str)

Note importanti:
- Le funzioni restituiscono stringhe malloc'd da liberare con vt_free_string.
- Il bridge non lancia eccezioni verso Swift: tutto è in try/catch e imposta last_error.
- Il polling va chiamato dal main thread di Swift ogni ~0.8 s.
- La sessione libtorrent usa auto_managed disabilitato per controllare pausa/ripresa
  dell'utente. In vt_add_magnet/vt_add_torrent_file il flag paused viene impostato o
  azzerato in modo esplicito: add_torrent_params::default_flags include paused, quindi un
  semplice OR lascerebbe i nuovi torrent in pausa.
- Il salvataggio resume avviene ogni 20 s e in vt_session_destroy.
  Il resume è salvato con lt::torrent_handle::save_info_dict: contiene l'info dict.
  Non togliere il flag: senza di esso al riavvio i torrent aggiunti da file perdono i
  metadati (dimensione e file a 0) e quelli in pausa non possono riscaricarli.
- removed_ids evita che alert tardivi di save_resume_data ricreino file di torrent rimossi.
  La stessa logica è applicata in destroy con requested_ids, per non scrivere alert vecchi
  e non decrementare male il contatore pending.
- prepared_save_path ripara percorsi non validi: se il save_path è un file, usa la sua
  cartella; se non esiste/ non è scrivibile, usa il default. Serve anche a recuperare
  resume data con save_path sbagliati (bug storico).
- Il bridge espone listen_port effettiva, is_listening e stato mapping UPnP/NAT-PMP.
  Gli errori di mapping si associano per indice E trasporto: UPnP e NAT-PMP numerano da 0,
  quindi confrontare solo l'indice può azzerare il mapping dell'altro trasporto.
- Lo snapshot richiede query_accurate_download_counters: senza il flag total_done e
  total_wanted_done avanzano per pezzi interi e progresso/ETA procedono a scatti.

Snapshot JSON (campi principali):
  torrents[]:
    id, name, state, state_code, progress, size, downloaded, uploaded,
    download_rate, upload_rate, peers, seeds, eta, finished, seeding,
    paused, sequential, has_metadata, save_path, files, ratio, added, error
  download_rate, upload_rate, total_download, total_upload, active, paused_count,
  dht_nodes, listen_actual_port, listening, portmap { tcp{...}, udp{...}, error }, port

  error è vuoto se status.errc non è valorizzato. Non usare errc.message() senza
  controllare errc: restituisce "Undefined error: 0".

Il bridge capta gli alert:
  save_resume_data, session_stats, portmap, portmap_error, add_torrent, torrent_error.
Il settings alert_mask include error, storage, status, port_mapping.

NON modificare il formato JSON senza aggiornare Models.swift e verificare la decodifica.
È stato usato un test Swift esterno per verificare VertexSnapshot contro il JSON reale.


7. TORRENT ENGINE (SWIFT)
-------------------------

TorrentEngine è un singleton @MainActor ObservableObject. Non creare altre sessioni:
usa TorrentEngine.shared.

Ciclo:
- Task di polling ogni 0.8 s.
- vt_session_poll -> vt_snapshot_json -> decode VertexSnapshot.
- Aggiorna torrents, stats, history; gestisce toast di completamento.
- Il toast di completamento usa unfinishedIDs (torrent visti attivi e non in checking):
  evita falsi "completato" per torrent già seed al lancio.
- Il dettaglio viene aggiornato ogni 3 poll; forceDetailRefresh dopo cambio priorità;
  select() azzera detail e fa subito una fetch.
- Il poll salta il motore reale in DEBUG se VERTEX_DEMO=1: mostra solo dati demo.

Aggiunta torrent:
- addMagnet / addTorrentFile validano la destinazione con preparedDestination.
- Se la destinazione è un file, usa la cartella che lo contiene.
- Se non è scrivibile, errore visibile.
- startPaused e sequential sono per-torrent nella finestra di aggiunta; i default sono
  nelle Impostazioni.
- Il percorso non viene più scritto nei default globali dalla finestra di aggiunta.

Preferenze (UserDefaults, dominio app.vertex.torrent):
- downloadPath, downloadLimitKB, uploadLimitKB, listenPort,
  dhtEnabled, upnpEnabled, startPaused, sequentialDefault, appearance.
- Preferences.resolvedDownloadPath ripara i percorsi-file.
- registerDefaults imposta i default.

Dati:
- Download predefinito: ~/Downloads/Vertex
- Resume: ~/Library/Application Support/Vertex/resume
- Non cancellare questi dati durante i test senza autorizzazione.


8. APPARENZA E UI
-----------------

- AppAppearance applica il tema a NSApp e a tutte le NSWindow.
- La finestra principale è una scena Window singola (non WindowGroup): aprire un magnet o
  un .torrent con l'app già attiva non crea una seconda finestra.
- La versione dell'app è mostrata nell'header (vX.Y.Z), nel sottotitolo e nella sezione
  Informazioni delle Impostazioni (versione e build) e nel pannello Informazioni su Vertex.
- Lingua: italiano se la lingua di sistema è italiana, altrimenti inglese. Le localizzazioni
  sono en.lproj/it.lproj con CFBundleDevelopmentRegion=en; un sistema non italiano ricade
  sull'inglese. Numeri e date seguono le impostazioni regionali del sistema (Locale.current).
- Testi statici SwiftUI (Text/Button/Label/Toggle) usano le chiavi italiane e sono
  localizzati automaticamente. Per stringhe dinamiche usare L()/LF() e aggiornare ENTRAMBE
  le tabelle. LF usa %ld/%@ e formato POSIX: niente separatore delle migliaia per porte e conteggi.
- preferredColorScheme NON è usato: il tema è gestito da AppKit.
- L'app è disponible in chiaro, scuro o sistema; il cambio è immediato.
- Le schermate Impostazioni e Diagnostica sono overlay custom (modalBackdrop), non sheet.
- La finestra "Aggiungi torrent" è un vero sheet macOS.
- Mantieni lo stile: sfondo con gradienti mint/viola, card arrotondate, progress ring,
  sparkline, testi in italiano o inglese, tema scuro/chiaro.
- Gli overlay decorativi hanno allowsHitTesting(false) per non bloccare i click.
- I controlli hanno contentShape per rendere cliccabile tutta l'area.
  Non rimuovere queste accortezze: hanno risolto bug reali di hit testing.

Pannello Diagnostica rete:
- Si apre dal pulsante "Porta" nella status bar, da Impostazioni > Rete > Diagnostica rete,
  dal menu Vista > Diagnostica rete oppure con Cmd-Shift-D.
- Mostra porta effettiva/configurata, stato ascolto, IP locale, nodi DHT,
  mapping UPnP/NAT-PMP TCP/UDP ed eventuale errore.
- "Testa porta" usa api.ipify.org e check-host.net, testa solo TCP e invia l'IP pubblico
  al servizio solo su richiesta. Mostra open/closed per nodo e permette di copiare IP:porta.
- Le mappature UPnP manuali non compaiono come "mapped": quella sezione riflette solo
  UPnP/NAT-PMP automatico. Il forwarding manuale va verificato con il test porta.
- check-host.net può essere lento/rate-limited/reachable; gestire gli errori senza crash.


9. DEBUG E SCREENSHOT
---------------------

DebugSupport.swift è compilato solo in DEBUG. Variabili utili:
  VERTEX_DEMO=1
      dati demo, nessuna sessione libtorrent reale.
  VERTEX_DEMO_SELECT=1
      seleziona il primo torrent dopo ~700 ms (apre il pannello dettagli).
  VERTEX_DEMO_SHEET=add | settings | diagnostics
      apre la relativa UI all'avvio.
  VERTEX_SNAPSHOT=/percorso/immagine.png
      dopo ~2.2 s cattura la finestra chiave e termina il processo (exit 0 in DEBUG).

Per avviare con env affidabile:
  ./build.sh debug
  launchctl setenv VERTEX_DEMO 1
  launchctl setenv VERTEX_DEMO_SHEET diagnostics
  launchctl setenv VERTEX_SNAPSHOT /tmp/vertex-diagnostics.png
  open -n dist/Vertex.app
  sleep 5
  launchctl unsetenv VERTEX_DEMO
  launchctl unsetenv VERTEX_DEMO_SHEET
  launchctl unsetenv VERTEX_SNAPSHOT

La cattura usa i layer della finestra, non screencapture (che può richiedere permessi).
exit(0) è usato per evitare che un sheet nativo blocchi la chiusura durante i test.


10. RETE, CGNAT E TEST PORTA
----------------------------

Test locale:
  lsof -nP -iTCP:6881 -sTCP:LISTEN
  lsof -nP -iUDP:6881
  nc -vz -G 3 127.0.0.1 6881

Test esterno:
  usare il pannello Diagnostica (check-host.net), oppure:
  curl -s -H 'Accept: application/json' \
    "https://check-host.net/check-tcp?host=PUBLIC_IP:6881&max_nodes=3"
  poi interrogare /check-result/REQUEST_ID.

Stato della rete dell'utente (non è un bug dell'app):
- Enel Fibra usa IPv4 privato statico + NAT su IP pubblico condiviso (CGNAT).
- La documentazione Enel dichiara IPv6 "Non disponibili".
- La WAN del router è nel range 100.64.0.0/10; l'IP pubblico visto da Internet è condiviso.
- Di conseguenza il port forwarding/ACL sul router non può aprire la porta verso Internet.
- Il pannello Diagnostica mostrerà la porta chiusa; è corretto.
- Soluzioni possibili: IP pubblico IPv4/IPv6 da un altro provider, VPN con port forwarding
  (NordVPN NON offre port forwarding), VPS con WireGuard/reverse tunnel, seedbox.
- Non suggerire DMZ o disattivazione globale del firewall come soluzione.

Firewall macOS dell'utente: Application Firewall attivo ma Vertex autorizzata.
Le regole ACL del router (Enel DX3301-T1) non sostituiscono il port forwarding/NAT.


11. KNOWN ISSUES / LIMITI
-------------------------

- Richiede macOS 27.0 e arm64 nella build attuale. Per supportare macOS precedenti o Intel
  bisogna ricompilare libtorrent/OpenSSL con deployment target inferiore e creare una
  build universale.
- Firma ad-hoc, non notarizzata. Su altri Mac Gatekeeper può richiedere clic destro > Apri
  o Impostazioni > Privacy e Sicurezza > Apri comunque.
- Interfaccia in italiano se il sistema è in italiano, altrimenti inglese; non sono previste
  altre lingue.
- Client volutamente minimale: niente RSS, ricerca torrent, scheduler, limite di rapporto,
  spostamento dati di torrent esistenti.
- Suite di test automatica presente nel repo: VertexTestRunner (eseguibile con ./build.sh test
  o swift run VertexTestRunner), che testa formattatori, modelli/JSON snapshot, preferenze e
  ciclo vitale del bridge C++. Workflow CI attivo su GitHub Actions (.github/workflows/ci.yml).
- Portmap error non distingue TCP/UDP: viene mostrato come errore generico.
- Il dettaglio può mantenere dati precedenti se una fetch fallisce (select() li azzera).
- make-dmg.sh usa hdiutil, che su macOS 27 stampa warning di deprecazione ma funziona.
- La DMG non è firmata/notarizzata; l'app è ad-hoc.
- check-host.net è una dipendenza esterna per il test porta.
- Non sono state aggiunte funzioni di proxy/VPN binding nel client.
- Il resume data e i download dell'utente possono contenere dati personali: non committarli.

Non c'è alcun segreto nel repository. Non inserire chiavi .p8, password app-specific,
token GitHub o certificati nel repo.

13. FIRMA DEVELOPER ID E NOTARIZZAZIONE (NON FATTE)
---------------------------------------------------

Non c'è alcuna identità di firma sul Mac. Per una distribuzione senza avvisi Gatekeeper:
1. Apple Developer Program + certificato "Developer ID Application".
2. Firmare prima le dylib in Contents/Frameworks con:
     codesign --force --timestamp --options runtime --sign "$IDENTITY" <dylib>
3. Firmare l'app:
     codesign --force --timestamp --options runtime --sign "$IDENTITY" dist/Vertex.app
4. Creare la DMG con ./Scripts/make-dmg.sh --no-build (NON rilanciare build.sh).
5. Firmare la DMG, notarizzare con notarytool, applicare il ticket con stapler.
6. Verificare con spctl e su un Mac con quarantena.
Sequenza indicativa (da adattare al certificato e al profilo Keychain):
  IDENTITY="Developer ID Application: Nome Cognome (TEAMID)"
  APP="dist/Vertex.app"
  xattr -cr "$APP"
  find "$APP/Contents/Frameworks" -name '*.dylib' -exec \
    codesign --force --timestamp --options runtime --sign "$IDENTITY" {} \;
  codesign --force --timestamp --options runtime --sign "$IDENTITY" "$APP"
  codesign --verify --deep --strict --verbose=2 "$APP"
  ./Scripts/make-dmg.sh --no-build
  DMG="dist/Vertex-1.3.2-macOS27.0-arm64.dmg"
  codesign --force --timestamp --sign "$IDENTITY" "$DMG"
  xcrun notarytool submit "$DMG" --keychain-profile "VertexNotary" --wait
  xcrun stapler staple "$DMG"
  xcrun stapler validate "$DMG"
  spctl -a -vvv -t install "$DMG"

Le credenziali notarytool si creano con store-credentials usando una API key App Store
Connect oppure Apple ID + password specifica; non metterle nel repository.
Non usare codesign --deep per firmare: firmare prima le dylib e poi l'app.

Se si firma con Developer ID, aggiornare build.sh per supportare un SIGN_IDENTITY
parametrizzato, altrimenti ad ogni build si torna alla firma ad-hoc.

- La documentazione utente è in README.md (inglese) e README.it.md (italiano); il changelog

  sempre entrambe le tabelle di localizzazione e mantenere lo stile.
